# 8010 回复可靠性与流程恢复

## 2026-10-16 备选先行、回答选路与主题失败恢复

本次用户确认的流程修订优先于下文旧的按维度直接提问、固定问题恢复和活动主题只讨论规则。信息充分直接规划；需要取舍时，既有 `proposal_clarification` 输出通常两个、最多三个较完整方向及一个区分其真实差异的问题。方向说明目标相关的水域／内部墙处理、焦点、机制、预期效果、代价和保留项，不输出格子修改或可解保证；只剩一个负责方向时在同一请求截止时间内接正式规划，没有方向时交付可靠失败分析并保留 `revision_needed`。

`proposal_options.py` 校验私有方向结构、组件范围、稳定 ID、Stage／地图签名和问句的比较对象。方向内容与问句存入原 `guidance_json.proposalDiscovery`，读取 API 不暴露这些内部字段，DesignContext 不接收备选。每轮澄清使用既有独立复核（6秒＋4秒）检查实际方向内容、正文、比较关系和权限，返回原句／方向 ID；有效正文和方向锁定，问句修复不能重写方向，方向失效则连同依赖问句一起修复。仍不可靠时返回原请求的可重试错误，不添加固定问题。最终可见内容须与复核方向一致，问题仍按实际显示数量计数。

`turn_understanding` 仅增加 `optionDecision` 小组件，保留完整方向在上下文中：排序偏好、排除项、explicit/inferred/unclear/revise、最新用户原文。格式／引用失效只修该组件；实际选路经原独立理解复核，不增加第三轮入口。用户选择只关联已显示内容，推断偏好是方案假设。被排除方向保留原身份，撤回排除须由最新原话和复核支持。方向更正可重建备选而不清空三问预算；最终选路投影进入需求／计划，实施策略只能尝试同方向与允许组件，不能静默替换明确选择。缓存键包括备选和选路。

活动方案主题的入口理解／复核失败，在写入新回答前记录 `retry_pending`、原问题数和消息键，直接报错；普通模式的短答也不能回退 `conversationOnly`。没有任何解析结果时使用原第二次机会重新请求；已验收字段才采用定向补丁。Python各受支持版本的异步超时分别归类，字段失败保留安全路径／原因码；无法追溯的历史失败仍未知。入口15秒、复核12秒及HTTP116／120秒预算均不增加。方案澄清提交也受原对话提交绑定保护，更新的消息或HTTP接收凭据使旧结果失效。

前端保留可恢复请求时继续原键重试；丢失本地请求且没有未完成用户Turn可恢复时，允许重新输入回答，以新键继续同一主题。Proposal模式开关仍锁于活动主题。方向回复的翻译使用原第二次翻译机会独立核对含义、选项、问句及权限，不把地图内部信息送入翻译或其复核；没有校验机会／失败则保留原文，逐条重试，不增第三次调用。普通只讨论恢复也复用权限语义复核。

用户中途请求解释某个备选、且没有给出选择时，只解释并保留待回答问题，三问用尽也不能把解释请求当成选项同意；该活动话题正文继续核对建议权限。用户明确更正方向且新语义已充分时，即使三问用尽也可以直接规划新方向，不沿用失效备选或增加第四问。

诊断仅增加方向数、策略版本和选择类别，不记录方向文本。专项离线故障注入见 `test_proposal_options.py` 和 Session三问边界、前端本地请求丢失测试；正常回归和离线评估不调用真实Kimi。不回填历史、不重写父Stage或旧Turn，模拟测试不证明真实理解率、恢复率或地图方案成功率。

## 2026-10-13 方案证据定向修复与阶段溯源

入口 `proposalUnderstanding` 的校验按服务器字段路径收集最多16项结构化错误，区分来源不存在／类型错误、空引用／非原文引用、条目结构和当前实体错误，另记录总数及截断标志。真实 Turn ID、临时 `latest` 和补丁外部引用 `user:<id>` 在修复提示中明确区分；服务器不自动重绑来源、不近似匹配引文、不补造设计意图或授权。只修失败字段或条目，锁定其他条目及有效基本理解；不可解析或无法独立验收的完整组件保留原组件恢复范围。合并后重新验收完整主题、历史目标/限制、权限和必要独立复核。明确、有效的复核拒绝停止本轮恢复，不把拒绝字段修成接受；技术缺字段才使用剩余的既有修复机会。入口至多两次，合法不确定仍通过Kimi形成理解并进入已有三问流程。

未点名对象的布局修改、语义充分性和是否需要澄清均由Kimi按用户原话及上下文判断，不新增关键词库或固定语义路由。当前平台固定权限仅允许水域与内部墙体；保护对象的引用及正常游玩推箱子不是实体初始布局修改的授权。未明确命名的实现对象属于方案假设，不记成用户明确要求。普通聊天、正文修复、既有正文/澄清复核和修改助手保持相同权限规则；修改助手不再收到搬动箱子/目标/玩家的指导或可写实体终态。当前API在候选冻结、执行重放和接受时复核真实差异；历史记录和通用低层工具保留，但不能绕过当前API权限。既有Kimi复核确认的正文缺陷沿原恢复槽处理，非橙卡正文的明确缺陷也锁定复核结果，不通过可选预算耗尽恢复成可靠正文。没有额外调用阶段或语义关键词检测。

`proposal-diagnostics-2026-10-13-v1` 复用 `proposal_pipeline_stage` 日志和 `reply_pipeline_diagnostic` 审计事件，覆盖理解/复核、澄清、需求/复核、计划/合同、候选/搜索/求解、冻结/呈现、挑战分支、执行和接受/提交。绑定HTTP请求、消息/动作键、Stage、来源卡片/方案及输入签名；每个HTTP尝试追加独立诊断，原键重试不重复创建业务Turn、决策或Stage。接受事务失败后的诊断另行追加，业务事务仍回滚。无有效会话或关联业务记录的拒绝不写研究诊断；SQLite不可用时审计无法保证写入，已发出的结构化日志仍可供定位。

错误 `details.proposalDiagnostic` 包含版本、至多96个阶段步骤、首次拒绝、最终失败及待重验组件。首次拒绝只是最早观察到的校验失败，不等于已经证明的根因；外层包装保留子阶段失败。成功请求清除最终失败，保留已经恢复的拒绝轨迹。修复分别记录 proposed、merged、revalidated、revalidation_failed、exhausted；merged只表示格式与合并通过。诊断不包含原话、模型输出、提示词、地图、坐标或凭据；无法分类的旧式校验保持 `UNCLASSIFIED_VALIDATION`，缺计数保持未知，不伪造定位精度。现有错误码、接口、研究数据、主截止时间和预算保持；其他阶段本轮接入诊断，未新增恢复流程。

只读报告新增独立 `proposalDiagnostics` 阶段、原因及修复统计；不算成正文请求或模型准确率，旧记录缺诊断为未知、不回填。专项离线覆盖见 `test_proposal_diagnostics.py` 和 Session入口/接受测试，并保留完整后端、前端及36例/2图离线验证。成功流测试改用合法水域变化，实体移动用于拒绝或历史展示测试。测试使用模拟模型，不证明真实Kimi恢复率；2026-10-13旧故障无法据此补写具体错误字段或根因。


## 2026-10-13 普通聊天联合复核与诊断

普通聊天在可靠正文之后，由已有 `intent_candidate_review` 同时审查意图和最多 24 个当前 Stage 的有效开放问题。取消该路径正文前的独立问题复核，回答问题不再排除橙卡。模型只返回服务器提供的 `answeredQuestionIds`，其余问题保持原状态；意图、呈现与问题字段分别验收，一项技术失败不丢另一项可靠结果。截断或不可解析的整体 JSON 不猜测恢复。方案话题与活跃分歧保持原专用流程。HTTP 120 秒、内部 116 秒、普通正文最多三次、可选累计 10 秒及 20 秒预留不变。

主模型决定、独立复核与最终卡片状态分开保留。合格主卡保留，否则选择复核的合格替代文本；卡片失败不把 verified candidate 改成 none。未展示候选只进审计，不创建隐藏倾向或确认/冲突状态。普通路径绕过旧关键词意图卡生成，有限暂定措辞正则不再否决经过语义复核的同义表达；证据、语义范围、确定性意图归因、地图事实、语言及伪成功仍检查。普通卡片表达修复仅返回 `cardText` JSON，锁定原文和 claims；正式补丁、合同、求解、旧卡与恢复协议不变。同一请求内相同文本/地图/绑定的成功确定性检查可复用，改变输入重新检查，不跨请求缓存。

用户明确授权的首次两条隔离真实 Kimi 请求中，一条同时交付卡片/问题更新，另一条发现正文修复失败后重走整轮复核、可选预算不足导致已通过卡片丢失。该路径已增加专项故障回归：已验证语义、卡片和问题锁定；已核实的正文语义缺陷属于必需恢复，原有下一复核调用只判断新正文与锁定 claims 的一致性，不重新生成/抄写语义与问题字段，不追加任务，不重置可选预算，仍受原主截止时间约束。该观察不能证明线上成功率变化，后续真实复测与固定测试分别记录。

第二次隔离复测的两条请求均交付正文、卡片和问题更新，其中一条仍需三次正文尝试；诊断定位到普通正文表达修复的 PATCH_VALUE_INVALID。普通正文表达因此也改为直接 `bodyParagraphs` 字段，保留锁定语义、语言/地图/伪成功检查，取消 valueJson 二次编码。正式补丁保持原样。这些小样本不构成稳定成功率或耗时结论。

服务端 `reply_pipeline_stage` 日志和现有 audit_events 内的 `reply_pipeline_diagnostic` 关联 HTTP requestId、消息幂等键、Stage、助手 Turn 及 `ordinary-harness-2026-10-13-v2` 版本，记录路由、正文/模型调用、联合复核解析、意图、问题、卡片选择/修复、最终投影和提交。每个 HTTP 尝试一个追加式诊断，不是另一次逻辑请求或模型尝试。尚未形成有效消息/失败记录的拒绝只记日志，不新增研究事件；诊断不保存提示词、模型原文、聊天正文、地图或凭据。保留原错误码和准确内部 failureStage，明确区分无需卡、未核实、预算不足、表达失败与并发失效。

响应新增 `X-Reply-Pipeline-Version`。前端在当前标签页 sessionStorage 的 `sokobanReplyDiagnosticsV2` 保存最多 200 条不含正文的接收、显示策略与 DOM 构建结果，关联 X-Request-ID、消息键、Stage 和 Turn；刷新保留，关标签页清除。无上传端点/网络请求/调试控件，存储失败不影响交付。浏览器诊断可通过开发者控制台读取该键；服务端提交成功不证明浏览器收到或用户实际看见卡片，DOM 构建也不是人类视觉质量评分。

只读报告新增意图复核、卡片提交、问题复核/更新的 observed/missing 指标，以及独立的 pipelineDiagnostics 阶段统计；旧记录缺字段为 unknown，不回填。固定回归见 `test_ordinary_harness.py` 与前端控制测试，包含联合交付、组件故障、零预算、同义表达、幂等、隐藏信息、前端过滤/渲染/响应故障和指标隔离。仅用户明确授权时执行少量隔离真实模型测试；不得创建生产 Demo、HTTP 会话或写研究数据库，观察结果与固定输出测试分开报告。

## 最小修复与证据约束补全（2026-10-12）

本轮补齐组件技术故障的恢复路径，不改变研究设计、授权、地图权限或状态恢复协议。正常专名（如 Kimi K2.6、AI）和少量自然英文在生成、翻译和显示中保留。中文历史展示不再把非白名单英文替换成“相关设计指标”；已知内部字段使用既有准确映射，未知内部标识只隐藏受影响句子，不调用模型、不改历史数据库。句子拆分保留数字小数点。可选卡片、链接和提示的语言失败局部省略，必需冲突和操作依据不随之省略。

补全先恢复确定事实，再调用必要的 Kimi 局部修复。当前地图数量及位置始终由 StageSnapshot 提供，不要求模型复制一份地图事实；操作缺少 `from` 时按当前格子恢复，不推断 `to` 或坐标。原本存在的约束可恢复，新的用户约束、固定数量、箱子位置和授权不能补造。合法空 focus、转换或可选信息保持为空。可靠的 Kimi 澄清问句可以单独交付，无可靠内容时返回错误，不补固定澄清正文。

`component_patches.py` 的请求内补丁包含 `componentId`、服务器白名单 `field`、编码单个 JSON 值的 `valueJson` 和 `evidenceRefs`。服务器冻结原内容、目标路径、类型及原证据签名；未知目标、改写锁定项、错误类型、重复补丁、未提供全部目标、伪造来源或绑定变化都拒绝。引用只是可追溯性检查，不代表语义或权限通过。补丁合并后仍调用各角色原有语义、Snapshot、权限、合同及求解校验，不直接写入会话或提交地图。模型修复使用 Kimi、thinking.disabled，沿用任务温度和完成预算。

补丁只是候选修复，不是通过标志。依赖关系记录为理解／复核 → 需求 → 计划 → 合同 → 操作 → 结构与求解 → 冻结 → 呈现／执行。上游改变后重新验证或重新生成其派生结果；纯呈现修复不改图。请求仍共享 HTTP 的116秒内部截止时间，组件补丁占用原任务的纠正机会，不另开嵌套重试；可选表达共用10秒预算并预留20秒。

提交前重新比对当前 Stage、地图与实体绑定、DesignContext、最新用户顺序和既有人工编辑讨论 HTTP 接收凭据；这些后台绑定不进入模型上下文。处理期间发生变化时，旧方案或动作返回 PROPOSAL_STALE，保留原地图。普通正文只有独立可靠时才交付，并去除旧的可选卡片、记忆、问题进度及状态信号；必要状态补齐继续走原证据恢复及 CAS，不以旧消息覆盖新状态。相同幂等键的重试不重复创建 Turn。

现有端点和错误码不变。错误摘要可增加 component、repairAttemptsUsed、maximumRepairAttempts；生成次数与局部修复次数分开显示。未知次数不默认三次；复核故障不标成网络上游故障。`proposalRequested` 保留原方案开关，未观察到可靠生成结果的审计布尔值保留 unknown。只读报告分别归类组件复核技术故障及补丁故障，不据错误码推断理解准确率。没有历史回填。

验收使用 `test_component_patches.py` 的补丁边界与真实校验入口故障注入，并保留原聊天、方案、挑战、翻译、保存、幂等、迟到恢复及前端回归。完整后端／前端测试和离线 semantic_eval validate 不调用真实 Kimi。测试通过证明这些路径的覆盖与拒绝边界，不保证模型一定能够修复所有失败，也不代表真实模型成功率。

2026-10-03，2026-10-07 更新修改交接与错误恢复；2026-10-12 确认上下文来源、聊天组件验收和必要状态自动补齐修订。现有接口兼容，Session 增加权威交互状态和辅助恢复端点；数据库表结构、模型隔离、研究记录及 Unity 协议保持不变。

## 2026-10-12 必要状态防错与自动补齐

人工编辑讨论的 engagement 只由结构化 `turn_understanding.humanEditEngagement` 判断一次：`engage / unchanged / unclear`。`engage` 必须引用当前用户准确原话；无关回复可 `unchanged`，真正不确定可 `unclear`，后两者不强制非空证据，也不重试直到同意。聊天不再重复填写 DISAGREEMENT/HUMAN_EDIT_ENGAGEMENT；后台沿用同一分歧身份并生成状态。旧标记解析器只保留显式兼容检查用途。入口理解和局部修复收到同一讨论来源及前面的助手提问，助手建议不能成为同意证据。

状态组件损坏先在本轮已有可选预算内单独修复；仍失败时可靠正文与待补齐任务一起提交。任务仅面向人工编辑 engagement，保存在现有 `audit_events`，绑定原消息键、真实用户/助手 Turn、Stage/version、后台分歧 ID、证据与地图签名、状态版本和提示版本；不保存模型原文或重复正文。新分歧 ID 后台生成；旧分歧只在读取时从可唯一定位的入口事件推导身份，无法定位不自动改状态，不回填历史记录。

页面可见、当前 Stage 且无前台写请求时，1 秒后自动提交独立 `POST /api/sessions/{sessionId}/component-recoveries/{recoveryId}/retry`；失败后隔 3 秒使用下一稳定尝试键，最多两次，跨刷新不重置。每次辅助请求总预算 10 秒、模型至多 8 秒、前端超时 12 秒；原聊天仍保持 116 秒内部截止、最多三次正文尝试和累计 10 秒可选预算。这不是重置原请求预算，也不新增产品 Agent。SQLite 短事务领取，15 秒租约，调用前计次，模型调用不占用数据库事务；重复键只重放，不重复调用。断线后只读刷新核实提交，连续读失败暂停页面自动触发。

恢复仅回放捕获的原消息：原证据固定保留，原提问经过讨论背景投影，此后同 Stage 最近 24 条完整对话用于复核撤回、纠正和替代；超过范围停止旧任务，不能截掉中间表达继续确认。`unclear` 进入 `needs_input`，`unchanged` 完成但保持原状态，两次技术失败进入 `exhausted`；不追加聊天，不要求用户重复同意。后续清楚的新表达仍通过普通聊天处理。

提交复核结果时原子核对同 Stage、同分歧、证据、地图、会话/deadline、当前状态及最新用户顺序。人工编辑讨论的 HTTP 接收凭据使用 `interaction_message_guard` 审计，在入口理解前登记、结束时关闭，120 秒租约处理进程中断；尚未写 Turn 的新请求也使旧复核失效，正在处理时恢复任务 `waiting_message`，只读等待且不消耗模型次数。并发变化丢弃本次结果，仅在仍有效且有剩余次数时重新复核。词语不能代替语义复核或形成授权。

成功仅清除当前 Stage 的人工编辑讨论阻断并记录 `disagreement_acknowledged`，不选择胜方、不确认倾向、不授权修改，不改历史 Turn/父 Stage、不生成卡片/方案/新 Stage。所有后续 LLM 上下文及当前控件读取 DesignContext 权威状态，不能从旧聊天标记重新恢复已清除的分歧。Session 的 `interactionState` 提供 version/revision、分歧身份/状态、实际阻断与恢复摘要；GET 不调用模型。恢复响应检查 Stage、Turn 顺序和 revision，不覆盖更新响应、输入、方案开关或未保存地图。历史卡片原样保存，旧响应字段缺失保留显示兼容。

审计 `component_recovery` 区分 pending/claimed/retry_pending/applied/completed_no_change/needs_input/expired/exhausted。只读 `reliability_report.py` 单列 `stateRecoveries`，关联原消息键，但排除正文请求数和正文成功率。回归见 `test_component_recovery.py` 及前端控制测试：短回答、坏字段、无额外成功调用、并发/撤回/换 Stage/截止/重复键/崩溃租约/预算耗尽、历史身份与输入草稿保留。固定输出测试不说明真实模型成功率。

## 2026-10-12 上下文与聊天组件验收

根因是入口理解、证据校验和正文使用不同的历史来源：普通入口只有最近用户文字却没有对应 Turn ID，正文主要接收最新消息，方案话题另有来源集合。统一 request-local `dialogueEvidence` 保留真实 ID、Stage、顺序和原话：当前 Stage 最近 24 条 Turn，以及活动话题全部已绑定用户来源。新主题通过已核实引用固定先前用户评价；解释目标不等于增加新授权、编辑范围或固定约束。聊天提示只投影历史讨论背景，剔除助手旧坐标/路线和已检测到的错误用户坐标；唯一当前地图依据仍为 StageSnapshot。新的上下文与提示签名使未完成旧理解重新核实，不回写研究历史。

普通理解失败允许只讨论模式：必须仍生成可靠 Kimi 正文，但关闭方案、意图和状态更新；显式方案按钮与卡片动作仍需核实后执行。有效基本理解锁定，方案字段局部修复，非方案消息中的意外方案字段直接省略。澄清的有效正文锁定后只修问题。意图、链接、补丁和问题进度独立验收；可选复核即使面对已确认倾向也不能仅因失败连带丢弃正文，明确识别到的正文语义缺陷仍需修复。

人工编辑分歧的状态字段失败时，在共用可选预算内进行一次局部 Kimi 修复；仍不可靠则保留可靠正文、原状态和方案锁，不重复入口卡，不写未经核实的状态成功结论。状态转换仍绑定最新用户原话，不代表选择胜方或接受地图。人工保存后的初始观察/比较仍完整原子提交。

句数、段数、短而相关的回答、合理澄清问句、列表和少量中英混用降为表达信号，不单独触发整轮重试。泛泛反问、明确答非所问、空白、截断、无法理解和无可靠正文仍报错；实现标识、错误地图事实、伪成功、操作授权、合同和求解继续检查。所有子任务共享原 116 秒截止时间；正文最多三次，可选组件累计最多 10 秒并预留 20 秒。普通聊天不增加固定兜底。

入口分类失败写入现有 `message_generation_failed`，`lastMessageFailure` 可投影当前 Stage 最新尚未交付的失败键，即使没有用户 Turn；后续成功或新消息不暴露旧诊断。只展示阶段、代码、尝试及请求标识，不展示提示词或模型原文。已交付聊天原键重放返回原结果，不重复写消息、卡片或 Stage。

回归见 `test_dialogue_continuity.py`、`test_sessions.py` 与既有组件测试，覆盖原话承接、窗口固定来源、助手来源拒绝、可靠短回复/澄清、可选复核故障、状态不变、显式操作阻断和幂等诊断。固定模型与故障注入不表示真实模型准确率或成功率；真实表现以部署后观测为准。

## 验收边界

| 检查 | 处理 |
| --- | --- |
| 当前地图事实、原文证据、明确方向/限制、授权、冻结差异、求解 | 不可靠的结论或操作不得交付；错误前提引出的相邻因果句一起清理 |
| 必需分歧/意图反馈状态、精确用户证据、人工编辑观察与比较 | 使用原流程次数和同一截止时间修复，失败保持原状态；不得删除必需字段来通过 |
| 句数、反思深度、重复、非必需卡片和表达长度 | 单独记录，局部修复或省略可选卡片；保留独立成立的可靠正文 |
| 可选 DesignContext 补丁、坐标链接、问题回答复核 | 无效字段丢弃或保持原状态，不影响已完成主流程 |

最低正文要求仍包含实质回复、可理解的分析和可靠事实。复核明确指出正文没有回答问题时仍须重试。单个 JSON 对象可去除代码围栏；多个对象、截断、缺失语义不猜测补全。

要求复核给出受影响 ID、问题类别、用户原文和修复指令。修复锁定其他合格要求，完整集合重新核对证据与覆盖。仅完整通过复核的记录可进入 `requirements_verified` 内部审计缓存；键覆盖 StageSnapshot、用户来源/内容、澄清回答、正式决定、DesignContext 投影、语言和规则/提示版本。

“否”是决定证据，不是原始设计要求。源卡、原始用户请求、主题回答和 canonical 理由共同构成后续方案的证据。历史错误的助手来源只有通过同请求、同 Stage 的真实用户记录才能恢复。旧候选指纹在模型、修复、搜索及末端验收共同排除。

可靠理解后没有合格候选时，预留的时间可生成一次经过地图、语言和伪成功检查的 Kimi 失败分析。无紫卡、无地图修改；choice_pending 仍等待可靠解决。要求解释不可靠、权限不成立或上游故障不得走此恢复分支。

## 方案语义与权限复核（2026-10-07）

方案主题的 `understanding` 分开记录目标、请求修改的组件、空间焦点和明确保留条件；每项绑定真实用户 Turn 和原文片段。地图对象作为焦点不等于请求修改该对象。短回答结合正在回答的问题及完整主题解释，不能覆盖既定修改范围。解释保存在现有 `turn_understanding` 审计结果中，由服务器附加 `semanticPolicyVersion=1` 和当前版本 ID；模型不能自行填写复核通过标志。历史正文和记录不改写，旧的未完成主题在下一次请求中重建并独立复核。

权限拒绝、编辑范围变化、既定目标/保留条件被移除及旧主题重建使用 `turn_understanding_review` 独立复核；最多两轮入口分类/复核，共享 HTTP 入口的 116 秒截止时间。每次分类上限 15 秒，关键复核上限 12 秒，不单独重置预算。未可靠核实时返回可重试错误，不输出权限断言、不落图。实际固定实体修改仍被拒绝，拒绝正文只列出经过复核的对象/属性及原文证据。`proposal_understanding_reviewed` 审计保留初步修改属性、纠正结果、原因和复核耗时；误判纠正记录不是模型准确率。

新主题按语义选择下一澄清维度，视觉目标不必须追问玩法机制或运输长度；充分时提前规划，仍共用最多三问预算。澄清提示词提供唯一当前 StageSnapshot、编辑权限及主题理解，用户目标与 AI 建议分开表达。数值/固定解法、意图归属及潜在保护实体编辑等风险信号只触发 Kimi 语义检查，不直接据关键词推断意图或删句。检查最多使用每次 10 秒主流程预算；可靠句子和问题分别保留、修复，未核实的必需语义不得用固定回复替代。

最终需求仍从原始用户证据编译并独立复核；主题理解只作为上下文，不是额外用户证据。缓存键新增主题理解与新提示版本。计划合同独立检查用户已指定的修改组件；修改助手继续只接收合同和当前地图，不接收聊天历史。视觉目标使用 `visual_composition`，不要求改变推箱路线；地图结构和求解验证不能证明美观达标，审美结论保持未机器验证。

回归包含不同实体/区域参照、真实受保护对象修改、范围纠正、原文缺失、旧主题、幂等重试和 HTTP 保存；测试入口为 `test_proposal_understanding.py`、`test_sessions.py` 与既有后端回归。固定输出测试不代表真实 Kimi 理解质量。

## 修改交接与候选验收（2026-10-07）

要求解释版本升级为 `interpretationVersion=2`，缓存提示版本为 `requirements-component-review-4-visual-and-original-scope`。编译/独立复核使用执行模块的同一份属性语义定义。定性“分散、整齐、平衡”使用 `appearance/seek`、空数值与 `unit=none`，不强制转换为数值跨度或玩法要求；保留原话和 Turn，美观效果始终未机器验证。

数量要求新增可选 `scope`，旧记录缺字段按 `all`。`original_cells` 只适用于水/内部墙数量，服务器以当前 Stage 原有格集合与候选同组件格集合的交集计算剩余数量，不接受模型自报原有格集合。“减少原有水域”允许同时增加其他水格，不暗示总量、总量保持或优先级。挑战重做继承同 Stage、来源仍有效的新版本已复核要求作为参考；纠正仅影响相关解释，最终仍独立复核完整覆盖。两次编译/复核上限不变，修复输入携带完整结构化问题与锁定合格项；超时、JSON 截断、非法 JSON 与语义不可靠分开记录，旧记录不回写。

数量增加合同默认允许同一授权组件添加和删除，明确禁止删除/保留位置时关闭相应操作；不能为改水补偿删墙或为改墙补偿删水。确定性搜索在既有位置顺序上补充最多每组件四个“删一格、加两格”原子候选，与单格候选共用去重、候选/beam 上限、最多 12 格修改及请求截止时间。组内中间地图不单独验收，最终完整候选仍通过权限、固定要求、结构、求解和方向检查。不能自行保留旧路线、总量或未指定格子。

新要求流程取消所有玩法修改必须接近一条 solver witness 的统一阻断，明确步数/推动指标仍直接检查方向和固定要求。实际相关修改可在目标部分完成或尚未改善时交付，并列出未实现/未核实目标；无改动、无关范围、反向或越权候选仍拒绝。排序维持明确优先级、当前重点、其他目标、更少修改和稳定顺序。审计区分确认无解与预算耗尽；预算耗尽仅表示验证未完成，不交付未经验证地图。最终验证通过才冻结真实差异，执行不为无范围限制的合同补上半径 1，不增加旧冻结卡修改；执行复验、接受建 Stage 和失败保留原图不变。

Session 的可选 `lastMessageFailure` 从现有 `message_generation_failed` 审计投影当前 Stage 最近用户消息键的失败代码、阶段/类别、重试状态与请求 ID，省略模型原文和提示词；同键已有助手成功回复则不再返回失败。前端遇到不可读 HTTP 错误/无效响应/超时后，只读刷新匹配捕获的 Stage 与消息键，使用服务端可靠摘要，无法匹配保留通用提示；已提交的成功回复清除旧失败。端点、错误码、原请求/理由/答案/挑战状态和幂等键保持兼容，不新增表或预算。

离线回归 `test_revision_flow_optimization` 验证属性范围、原有水格与净增、定性视觉未验证、步数未变、同组件补偿、独立复核交接和结构化修复、截断/超时/无解/预算区别。`test_sessions` 覆盖“视觉要求 → 只加水 → 质疑减少原有水域 → 否 → 删加新卡 → 执行 → 接受”的真实 HTTP 状态转换、冻结远距离差异、同键重试及失败摘要过滤；前端回归覆盖不可读响应的摘要匹配。固定模型输出测试只证明流程覆盖，不证明真实理解准确率。

## 预算和提交

- 普通聊天和当前要求策略的新方案：总预算 120 秒，HTTP 入口建立内部 116 秒绝对截止时间，所有内部调用共享。
- 普通正文最多三次；要求编译/复核和理由评审保留各自两次上限。旧冻结卡的执行路径保持兼容。
- 可选工作累计最多 10 秒，剩余不足 20 秒不启动；必需语义复核使用主预算。
- 正文与必需状态按逻辑单位提交；失败可以保留已保存的用户轮次，重试复用原键，不重复写卡片、问题或版本。
- 手工保存的可解 Stage 保留，观察与比较两条评审消息完整提交；失败重试评审，不重复创建 Stage。
- 翻译每个轮次独立提交；部分成功的错误包含已完成和待重试 ID，只读刷新保留成功结果，失败项显示原文。
- 浏览器成功响应必须满足实际端点契约，125 秒消息超时覆盖发送、读取正文和解析；异常后只读刷新确认已提交状态。重试闭包捕获原文本、动作、Stage、草稿和幂等键。

## 日志与指标

组件诊断包括组件、结果、失败代码、依赖与可修复性；生成日志记录各阶段尝试/耗时、保留/修复/省略，以及正文和方案结果。审计新增事件使用现有表，无迁移：

- `requirements_verified`：仅完整复核通过的要求与缓存键，不显示为卡片。
- `reply_delivery_outcome`：生成、正文交付、完整质量、可执行方案、组件结果与兜底来源。
- `message_generation_failed` / `reply_generation_failed`：失败尝试；既有 `challenge_reason_review_pending` 也进入报告。

只读汇总命令（时间为 UTC；应从本次部署时刻起）：

```powershell
python CoCreationPrototype/Backend/reliability_report.py path/to/cocreation.sqlite3 --since 2026-10-03T09:00:00
```

按会话和幂等键合并重试，分别统计首请求与重试后模型生成、可靠正文和完整质量通过率。完整质量表示记录的组件没有剩余质量/省略问题，是运行检查指标，不是人工审美评分。快照开场兜底与确定性回执单独统计，不计作 Kimi 正文成功。已请求方案单独统计验证成功数及比例；翻译的独立记录不冒充新的聊天正文。少量真实请求不能支持稳定成功率结论。

## 2026-10-06 小范围观测与离线评测

本轮仅增强只读 `reliability_report.py` 并增加独立评测工具，不修改服务运行链、前端、提示词、授权、Stage 或研究规则，不增加数据库表或新事件。

```powershell
python CoCreationPrototype/Backend/reliability_report.py path/to/cocreation.sqlite3 --since 2026-10-03T09:00:00Z --until 2026-10-06T08:00:00Z --format text
python CoCreationPrototype/Backend/semantic_eval.py validate
```

报告支持 JSON/简洁中文、任务分组、问题类别、最多三条匿名案例引用、重试后正文交付和已记录生成耗时 P50/P95。优先问题按最终未交付正文的逻辑请求数，再按涉及请求数排序。错误码只用于分类观测到的症状，不判定用户被误解或检查误伤；正文交付与有效方案分别统计。空报告和缺失数据不代表没有故障。

口径修正：请求按会话、任务、消息键归并，质疑理由复核并入消息任务，开场与聊天不会因复用键合并。多条审计结果只表示有多个结果记录，不等于内部模型尝试或精确 HTTP 重试次数。模型生成/质量缺失布尔字段为未知；各指标 `total` 保留合格逻辑请求数，`observed` 为该指标有记录的数，`rate` 使用 `observed` 分母，`missing` 单独列出。保留首条记录中的方案申请，以免重试成功遗漏分母。时段使用 UTC 或明确时区，结束时间不包含在内；SQLite 以只读方式打开并显式关闭。

这版报告不读取聊天原文，不输出完整会话/消息身份或模型错误原文，只输出匿名引用和观测时间。浏览器未收到响应、审计事件之前的分类失败、人工语义质量、Token 费用尚未覆盖，不能从现有记录推断。

固定集包含 36 个合成入口理解案例、两张可解地图，支持离线验收、输出评分和前后比较。真实 Kimi 采样单独由 `run --live` 启用，独立运行，不创建或覆盖正式/demo 数据。案例预期与人工说明不进入模型上下文。完整操作与当前范围见 [入口语义评测说明](Backend/evaluations/README.md)。
